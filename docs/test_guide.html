Test Guide

QAAI (qaai-may23) · generated from the codebase 2026-06-08

This guide covers how to set up, install, and run the test suites under tests/api and tests/integration, the default fixture files each test uses, and how to run the tests against your own custom input files.

Setup & install

QAAI uses uv and requires Python ≥ 3.12 pyproject.toml:9.

uv sync --frozen        # install locked dependencies (incl. pyjama, vendored locally at libs/pyjama)

pytest configuration pyproject.toml:44-48: asyncio_mode = "auto", test path tests/, and a single marker — integration ("marks tests that make real LLM API calls").

Environment variables for tests

Integration tests read their own live-LLM credentials from a repo-root .env tests/conftest.py:155-183:

PYTEST_API_KEY=<your-key>
PYTEST_BASE_URL=<your-api-url>
PYTEST_MODEL=gpt-4o-mini
Production guard. The real_client fixture rejects any PYTEST_BASE_URL containing the string "prod" to prevent accidental production charges tests/conftest.py:167-172.

Test runs are isolated from server runs: logs are written under logs/tests/ (set via settings.log_base_dir before qaai.api.main is imported) tests/conftest.py:21.

JSONL fixtures are newline-delimited; each line is a self-contained graph-input object. The hazard test assembles its HazardRowWithTraceMatrix input programmatically from the Excel + PyJama fixtures (there is no single hazard_full_traceability.jsonl).

Running with custom files

Each integration test accepts CLI options tests/conftest.py:55-81: --input-file (a bare fixture filename — JSONL for RTM/TC, .xlsx for hazard) and --pyjama-file (hazard traceability JSONL).

# RTM / test-case: --input-file is the JSONL of input rows
uv run pytest tests/integration/test_suite_reviewer/pipeline.py::test_test_suite_reviewer \
  --input-file=locating_device.jsonl

# Preview which items a file expands to, without spending any LLM calls
uv run pytest tests/integration/test_suite_reviewer/pipeline.py::test_test_suite_reviewer \
  --input-file=locating_device.jsonl --collect-only

# Run a single row by its id
uv run pytest tests/integration/test_suite_reviewer/pipeline.py::test_test_suite_reviewer \
  --input-file=locating_device.jsonl -k REQ-PUMP-001

# Hazard: --input-file is the SHA .xlsx; --pyjama-file overrides the traceability JSONL
uv run pytest tests/integration/hazard_risk_reviewer/pipeline.py::test_hazard_risk_reviewer \
  --input-file=software_hazard_analysis.xlsx --pyjama-file=pyjama_response_unified.jsonl

Adding your own fixture

  1. Drop the file into a fixtures subdir — tests/fixtures/local/ is recommended for project-specific data, e.g. tests/fixtures/local/my_requirements.jsonl.
  2. Match the reviewer's graph-input schema per row:
    • RTM: {"requirement": {...}, "test_cases": [...], "design_docs": [...]}
    • TC: {"test_case": {...}, "requirements": [...], "design_docs": [...]}
  3. Run by bare filename: --input-file=my_requirements.jsonl (found via the search order above, unless shadowed by a same-named file in mock/ or gold/).

Run artifacts

Session-scoped recorder fixtures (jsonl_recorders / _tc / _hz) append each input/output and generate the HTML viewer from outputs.jsonl at session teardown tests/conftest.py:373-415. Per session, under logs/tests/run-<timestamp>/:

  • inputs.jsonl / outputs.jsonl — recorded records
  • viewer.html / viewer_tc.html / viewer_hz.html — generated viewer
  • qaai.log — node/app logs for the run
  • hazard_pipeline_state.json — full hazard graph state (hazard test only)
