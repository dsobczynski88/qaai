AI model settings

API_KEY, API_BASE_URL, and API_MODEL configure the RateLimitOpenAIClient built at app startup qaai/api/main.py:71-77. Any OpenAI-compatible endpoint works (OpenAI, Ollama, vLLM, Bedrock via langchain-aws). The rate/token settings (MAX_REQUESTS_PER_MINUTE, MAX_TOKENS_PER_MINUTE, MAX_OUTPUT_TOKENS) feed the client's proactive RPM/TPM limiter; the TOKEN_COST_* rates drive the cost figures in token_usage.jsonl qaai/core/telemetry.py.

JAMA credentials

The three JAMA_* variables enable live baseline fetching for the RTM and test-case endpoints. When unset, those baseline reviews fail at job time with "PyJama is not installed — JAMA baseline fetching unavailable."; the hazard Excel upload path needs no JAMA. Set PYJAMA_TEST_MODE=true (or per-request test_mode) to fetch baselines from the on-disk cache only, with no live API calls — useful for offline/repeatable runs.

Caching

The review cache is a 3-tier write-through store shared by all three reviewers qaai/core/cache.py:

  • Tier 2 — Redis (optional, enabled by REDIS_URL; 24 h TTL; degrades gracefully if the package/host is unavailable).
  • Tier 3 — Disk JSON at {CACHE_DIR}/{entity_id}/{node}_{prompt_version}.json — the durable regulatory evidence; survives restarts.

Cache key: review:{entity_id}:{node_name}:{prompt_version}, where entity_id is a REQ-* (test suite), TEST-* (test case), or HAZ-* id. Set ENABLE_CACHE=false to disable the cache entirely (no manager is created) qaai/api/main.py:93-100.

Per-run cache mode

Each run threads a cache_mode through graph state qaai/agents/shared/nodes.py:122-137:

ModeBehavior
offNo reads or writes — recompute everything.
partial (default)Cache every interim node, but always re-run the graph's final node (synthesizer / aggregator / final assessor) for a fresh result.
fullCache the final node too. Used internally for the hazard reviewer's embedded RTM subgraph (cached as one req_id-keyed blob).
The API's "Use cached results" checkbox (use_cache) maps only to partial (checked) or off (unchecked) qaai/api/routes.py:68,91,135. full is not reachable from HTTP. Cache invalidation is by prompt version: bump a prompt's version and its cache key changes, leaving old entries untouched.

Prompt sets

Each LLM node renders a versioned Jinja2 template resolved by PromptConfig qaai/core/config.py:17-79. Templates live at qaai/prompts/<role>/<version>/template.jinja2 with a sidecar meta.yaml, and are rendered by render_prompt(path, **vars) qaai/utils.py. A prompt set is a named manifest that pins a version per role, letting you swap a whole bundle at once.

Manifests live in qaai/prompts/sets/*.yaml, e.g. test_suite_reviewer_v1.yaml:

name: test_suite_reviewer_v1
component: test_suite_reviewer
description: |
  Baseline RTM reviewer prompt bundle.
prompts:
  decomposer: v5.0.0
  summarizer: v4.0.0
  coverage: v7.0.0
  synthesizer: v7.0.0
status: production
authored: '2025-05-05'
parent_set: null

Shipped sets include test_suite_reviewer_v1..v4, test_case_reviewer_v1..v2, and hazard_risk_reviewer_v1. List them programmatically with list_sets(status=...) qaai/prompts/_registry.py:108-126.

Create a new prompt set

  1. Author the templates. For each role you want to change, add a new version directory with both files: 
    qaai/prompts/<role>/v<MAJOR.MINOR.PATCH>/template.jinja2
qaai/prompts/<role>/v<MAJOR.MINOR.PATCH>/meta.yaml
    Copy an existing meta.yaml for the expected fields (role, version, component, status, changelog, target_models). The role's on-disk directory is derived from PromptConfig's default path for that field qaai/prompts/_registry.py:44-57 (e.g. role coverage → directory coverage_evaluator).
  2. Write the manifest. Create qaai/prompts/sets/<set_name>.yaml with name, component, a prompts map of role → version, and status (e.g. experimental or production).
  3. Validate. load_set("<set_name>") qaai/prompts/_registry.py:60-105 resolves every role/version and raises FileNotFoundError if a template or meta.yaml is missing.
uv run python -c "from qaai.prompts._registry import load_set; print(load_set('my_set_v1').prompts.keys())"

Select a prompt set at run time

Set the PROMPT_SET environment variable to the manifest name. The Settings.prompt_config property lazily resolves it via PromptConfig.from_set(...) and caches the result qaai/core/config.py:133, 142-149; when unset, the built-in default PromptConfig() versions are used.

# .env
PROMPT_SET=test_suite_reviewer_v4

# or per process
PROMPT_SET=test_case_reviewer_v2 uv run uvicorn qaai.api.main:app
Because the cache key includes each prompt's version, switching prompt sets naturally produces fresh cache entries — old results for prior versions remain on disk as evidence. See Caching.
